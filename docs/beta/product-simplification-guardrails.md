# Product Simplification Guardrails

Beta objective: a stable, coherent PawStreak that 10–25 real dog parents can use repeatedly without founder intervention.

Do not default to new features. Protect the core loop.

## Core loop to protect

Discover → choose → go → remember → progress → discover again.

Every change should answer yes to at least one:

1. Does it help someone give their dog a better day?
2. Does it strengthen the core loop?
3. Does it increase likelihood of another adventure?
4. Does it improve emotional payoff?
5. Does it reduce friction?
6. Can we measure whether it worked?

## Keep prominent for beta

- Today
- Explore / discover adventure
- Adventure detail
- Quick Walk
- Active adventure
- Finish adventure
- Save memory/photo
- Journey
- Share card
- Reminder prompt/settings
- Pack only if invite flow validates cleanly

## Improve only if beta evidence shows friction

- Onboarding tutorial
- Completion reward/payoff
- Location unsupported copy
- Empty Journey state
- Share fallback copy
- Push reminder explanation
- Adventure card hierarchy

## De-emphasize during beta

- Community
- Heavy achievements
- Complex rewards
- Large challenge systems
- Training as a major tab
- Calendar integration depth
- GPS route recording
- City content hub
- Mascot animation rewrite
- Big visual/game overhaul

## Remove from production surface if found

- Fake activity numbers
- Fake community posts
- Fake dog/social data
- Demo badges/data outside `/demo/app`
- Any copy implying direct Instagram publishing if it is only native share sheet
- Any feature that looks tappable but does not complete a real action

## Default beta answer to new ideas

If it does not fix a P0/P1 or make the core loop clearer, write it down and defer it.

Good beta discipline is saying no to the shiny thing until the real loop works.
